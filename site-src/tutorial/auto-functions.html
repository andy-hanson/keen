Some functions can have their bodies generated automatically.

main void() a strings = ("a", "b") to b strings = (2, "a")::(string repeat) to info log "{a == a} {a == b}" info log "{a <=> b}" info log "{a.to::json} {b.to::json}" show string(a comparison) "{a.to::symbol}" strings union(string[], string repeat) == bool(a strings, b strings) <=> comparison(a strings, b strings) to json(a strings) repeat[t] record(count nat, value t) ==[t] bool(a t repeat, b t repeat) t equal <=>[t] comparison(a t repeat, b t repeat) t compare to[t] json(a t repeat) (json, t) to

Auto functions can be generated for any record or union type where the function has an implementation for the record's fields or the union's case types.

Currently supported auto functions are:

Function Result for union Result for record
== If the values are the same case type, calls the == function for that type; otherwise false. Calls the == function for each corresponding field; true if they all return true.
<=> Case types declared first compare less.
If the values have the same case type, calls the <=> function for that type. 		Compares each field in the order they were declared.
to json A JSON object with one key that is the name of the case type. Then calls to json for that type. A JSON object with one key for each record field. Calls to json for each field value.

In order to generate an auto function, the same kind of function must be implemented for each record field type or union case type.
For example, == for strings depends on == implementations for string[] and string repeat.
(The == implementation for string[] comes from the standard library.)
The member's implementation can come from spec, as in to[t] json(a t repeat) (json, t) to.

An auto function doesn't have to be declared next to the type, but it won't work if some of the type's members aren't visible at the declaration of the auto function.
Meaning: You can declare an auto function for a fully public type anywhere.
