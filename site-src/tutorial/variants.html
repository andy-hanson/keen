Variants

A variant is an alternate way of writing a union; instead of listing all the case types directly in the variant, the type declares that itself using the case keyword.

This leads to differences with unions:

  • Variants are open-ended. Since other modules could declare new case types for the variant, you can never write a match that handles all possible case types.
  • Due to the above, declaring methods is the only way to be sure a variant will be implemented for every type.
  • Method implementations are looked for in the module containing the case type, not in the module containing the variant.
    This means that variants allow you to call code indirectly without creating circular dependencies.

As with unions, case is not a subtype relation ship; the variant type and case type variant need explicit conversion.
There is also no inheritance. Making a type a case doesn't alter the type, it alters the variant to have a new member.

case parses like any other modifier and can be mixed with them. A type can have any number of case declarations. So you could write: r record(xs nat mut[]) mut, foo case, bar case.

main void() info log 10.crow.show info log duck.show c crow = 11, info log c.to.show bird variant # These could even go in a different module. crow record(height nat) bird case duck record bird case show string(a bird) match a as crow x "A {x.height}cm crow" as duck "A duck" # 'else' is required for variants else "Something else"

Here's the same example using methods instead of match:

main void() info log 10.crow.show info log duck.show bird variant show string() crow record(height nat) bird case duck record bird case show string(a crow) "A {a height}cm crow" show string(_ duck) "A duck"

Each case generates these functions:

  • A to function for converting to the variant. E.g., to bird(a crow)
  • A function with the type's name that converts back from the variant to an option of the type. E.g., crow crow?(a bird).
  • For records, a function with the type's name that constructs it as a variant directly. E.g., crow bird(height nat). (So you can write 10.crow instead of (10,)::crow.to.)
main void() m m = 7, v v = m to back m? = v m if x ?= back info log "{x value}" () v variant m record(value nat) v case

Interfaces

Interfaces are nearly the same as variants, but you can't match on an interface or convert back to a case type.
An interface value can only be used for its methods.

main void() a i = 1 r # Not allowed: # back r? = a r info log a.show i interface show string() r record(x nat) i case show string(a r) "x={a x}"

Interface vs Union vs Variant

So why does Crow have these three similar kinds of type?
union and interface are on opposite sides of a spectrum; union is fully visible and interface is fully abstracted. When you have a type that is used only internally to a module, make it a union. Also use a union if you want to commit to a particular set of case types.

Use an interface for cases where you don't want to expose anything about a type except the methods you have chosen.

Use a variant only rarely, when you want to allow users to break out of the interface by converting to a case type.
An example use is exception. Code using exceptions wants to be able to catch a particular exception type it defines, but the module that defines exception doesn't know all exception types up front.
