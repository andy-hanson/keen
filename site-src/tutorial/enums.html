Crow supports enum and flags types mostly for compatibility with C, but you might find them useful in other contexts.

Enum types

An enum type is a type that has only a specified set of possible values.
It's like a union where all the case types are empty.
This restriction brings with it easy conversion to/from a number or string.

main void() info log "{left.opposite.to::symbol}" direction enum(left, right) to symbol(a direction) opposite direction(a direction) match a as left right as right left

Declaring the enum generates functions left and right returning enum values.

match expressions work the same for enums as they do for unions.
The similarity makes it easy to change an enum to union (or vice versa) without breaking too much code.

Enum storage type

By default, enums are stored as a nat32, but you can make it a different size of nat, or even an int.

main void() info log "{left.to::nat8}" direction enum(left, right) nat8 storage to nat8(a direction)

You can also choose what integer values are associated with each value. (The default is 0, 1, 2, ... like in C.)
Doing so requires you to use the expanded syntax with one line per enum member.

main void() info log "{left.to::int16}" direction enum int16 storage left = -10 right = 10 to int16(a direction)

Differences with C

In C, "enums" don't really declare types; they just declare names of integers. A variable in C declared with an enum type might have any integer value, including those not declared in the enum.

In Crow, the declared enum values are the only valid values.

Auto funs for enums

In addition to the usual auto funs ==, <=>, and to json, there are more auto funs for enums to convert to or from the storage type integral or symbol.

main void() info log "equal: {x == y}" info log "compare: {(x <=> y).to::symbol}" info log "json: {x.to::json}" info log "to nat: {x.to::nat8}" info log "from nat: {1::nat8.to::e? ?? x}" info log "to symbol: {x.to::symbol}" info log "from symbol: {"y".to::e? ?? x}" info log "members: {" " join for x : members; "{x}"}" e enum(x, y) nat8 storage == bool(a e, b e) <=> comparison(a e, b e) to json(a e) to nat8(a e) to e?(a nat8) to symbol(a e) to e?(a symbol) members e[]() show string(a e) a.to::symbol to

Notice how converting back to the enum returns an option, since not every symbol or nat8 corresponds to an enum value.

Flags types

While enum types store one of the choices, flags types store any number of the choices.

main void() naked clothing = () info log "{naked}" fully-dressed clothing = shirt | pants | shoes info log "{fully-dressed}" info log "{naked can-serve}" info log "{shirt can-serve}" info log "{fully-dressed can-serve}" clothing flags(shirt, pants, shoes) to json(a clothing) show string(a clothing) "{a.to::json}" can-serve bool(a clothing) (shirt | shoes) in a

Declaring a flags type will generate the following functions (no declaration needed):

Signature Description
new f() Empty value: no flags are set.
~ f(a f) Negation: All flags not set become set and vice versa.
| f(a f, b f) Union: All flags in either a or b are included in the result.
& f(a f, b f) Intersection: Only flags in both a and b are included in the result.
in bool(a f, b f) True if all flags in a are set in b. In other words, b must be a superset of a.

As with enums, you can specify the backing type and exactly what value each flag has.
Make sure they are powers of 2.

main void() info log (shirt | shoes).to::nat16.to-binary clothing flags nat16 storage shirt = 0b00100 pants = 0b01000 shoes = 0b10000 to nat16(a clothing)

Flags types have the same auto funs as enum types, except they don't convert to a symbol but to a symbol[].

main void() a f = x | y info log "{a.to::symbol[]}" f flags(x, y) nat8 storage to symbol[](a f) show string(a symbol[]) " " join for x : a; "{x}"
